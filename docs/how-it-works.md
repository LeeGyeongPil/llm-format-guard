# 동작 원리

`guard()` 가 안에서 하는 일을 순서대로 풉니다. 모델 호출은 최대 2회(첫 답 + 수선 1회)입니다.

## 1. 왜 모델이 지시를 놓치나

대화가 길어지면 첫 턴의 "세 줄로"는 멀어지고, 마지막 메시지는 "이것도 부탁해"처럼 짧아집니다. 지시가 가장 최근 입력에 없으니 모델이 일반적인 길이로 답합니다. 그래서 이 라이브러리는 지시를 **기억해 두었다가 눈앞에 다시 놓습니다.**

## 2. 제약 추출 (`detect`, `Ledger`)

- `detect()` 는 정규식 한 벌로 메시지 하나에서 `(축, 비교 방식, 값)` 을 뽑습니다. 예: "항목 5개로" → `items le 5`.
- 모호하면 버립니다. 단위 없는 "5개", "이 자료"의 한자어 글자, "각 줄 30자"처럼 항목별 복합 조건은 잡지 않습니다.
- "세 줄로"는 상한(`le`)으로 읽습니다. 불만 대부분이 초과이기 때문이며, "정확히", "딱"이 붙을 때만 `eq` 입니다.
- `Ledger` 는 최근 6턴의 제약을 보관합니다. 같은 축은 최신이 덮어쓰고(`chars`와 `chars_no_space`는 한 축, 표·목록도 한 축), "길게 써도 돼" 같은 해제 표현이 나오면 지웁니다. 최대 5개.
- 1200자를 넘는 사용자 메시지는 붙여 넣은 글로 보고 앞 300자와 뒤 300자만 읽습니다. 기사 속 "세 줄로"가 제약으로 잡히는 걸 막기 위해서입니다.

## 3. 재주입

`Ledger.render()` 가 만든 `[활성 제약]` 블록(긍정문: "답은 3줄 이하로 쓴다.")을 마지막 사용자 메시지 바로 앞에 끼웁니다. 원래 메시지 목록은 바꾸지 않고 새 목록을 만듭니다. "~하지 마"보다 "~로 쓴다"가 따르기 쉬워 긍정문으로 씁니다.

## 4. 결정적 측정 (`measure`, `check`)

- 코드블록(```)과 `<think>` 태그를 먼저 걷어 냅니다.
- 마크다운 표는 표 줄로 따로 세고(구분선은 행으로 세지 않음), 글머리 기호와 `*`, `_`, `` ` `` 는 글자 수에서 뺍니다. 표 셀의 보이는 글자도 글자·단어 수에 포함합니다(구분선·파이프 제외).
- `loose`(기본)는 머리말 한 줄을 봐줍니다. 상한은 "줄 수"와 "머리말 뺀 줄 수" 중 작은 값, 하한은 큰 값으로 판단합니다. `strict` 는 원시 계수입니다.
- 위반 메시지는 숫자로 나옵니다: "현재 4줄, 목표 3줄 이하".

## 5. 조건부 수선 (`repair`)

1. 위반이 있으면 위반 메시지를 붙여 한 번만 다시 쓰게 합니다.
2. 수선 답의 점수 `(위반 수, 목표와의 거리 합)` 이 원래 답보다 사전식으로 **엄격히 작을 때만** 채택합니다.
3. 아니면 원래 답을 유지합니다. 모델 호출이 실패해도 원래 답을 유지합니다.

예: 5행 표를 요청했는데 수선 답이 3행 글머리 목록이면 위반 수는 1 → 1 로 같고 거리는 0.67 → 1.0 으로 커지므로 거부됩니다.

## 6. 한계

- 정규식이라 표현 범위가 좁습니다.
- 한국어 내장 문장 분리기는 마침표 없는 한 줄의 여러 문장을 1문장으로 셉니다(줄 단위로는 셈). 선택 기능 `kss` 로 보완합니다.
- 실제 모델로 검증하지 않았습니다. 평가 수치는 연습용 목(mock) 모델과 직접 쓴 녹화 답변 기준입니다.
